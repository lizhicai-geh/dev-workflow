# 数据库迁移规范

## 基本原则

- 每次变更对应独立迁移；
- 已执行迁移不得修改；
- 迁移脚本应可重复验证；
- 大表变更评估锁表和执行时间；
- 删除字段前先清理旧代码依赖；
- 数据迁移必须提供对账方式。

## 推荐流程

```text
Expand
→ 新旧代码兼容
→ Migrate
→ 验证一致性
→ Switch
→ Contract
```

## 数据迁移任务必须说明

- 数据范围；
- 数据量；
- 预计耗时；
- 是否支持断点续传；
- 是否可重复执行；
- 错误数据处理；
- 对账方法；
- 回滚或补偿方法。

## 发布检查

- 迁移在类生产数据量验证；
- 应用版本与迁移顺序明确；
- 失败后的恢复步骤明确；
- 不将反向 SQL 视为唯一恢复手段。
