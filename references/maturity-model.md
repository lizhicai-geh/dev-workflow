# 开发工作流成熟度

## 评分

对每项能力附可复核证据并评分：`0=不存在`、`1=有文档但依赖人工`、`2=稳定且可重复`、`3=自动化并持续度量`。无证据按 0；维度均分仅用于改进排序，不能抵消关键缺口。

当前等级取所有必需能力满足阈值的最高级：

| 等级 | 必需能力 | 额外阈值 |
|---|---|---|
| V1 可开发 | 需求、任务、Git 分支、基础测试、本地开发 | 每项 ≥1 |
| V2 稳定交付 | V1、DoR/DoD、CI、测试策略、迁移规范、测试环境与发布验证 | 新增项 ≥1；CI 和发布验证 ≥2 |
| V3 生产运行 | V2、灰度/开关、可观测性、故障恢复、安全扫描、数据质量监控 | 新增项 ≥1；可观测性和恢复 ≥2 |
| V4 持续优化 | V3、交付与 AI 质量指标、自动化治理、架构债务、持续复盘 | 新增项 ≥2；至少一项治理能力 =3 |

## 可接受证据

- 需求/门禁：模板、已完成 Issue/PR、门禁记录。
- CI/测试：流水线配置、最近结果和失败阻断记录。
- 数据/发布：迁移与演练、对账、恢复、发布单和发布后验证。
- 运行/安全：仪表盘、告警、响应记录、扫描和权限审计。
- 效能/改进：指标、复盘及改进项关闭记录。

报告逐项列证据和评分，给出当前等级、关键缺口及分阶段改进路线。
