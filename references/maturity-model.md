# 开发工作流成熟度模型

## 评估方法

1. 为每项能力收集可复核证据，例如配置、流水线记录、测试报告、发布记录、告警或复盘。
2. 逐项标记：`0=不存在`、`1=有文档但主要靠人工`、`2=稳定执行且可重复`、`3=自动化并持续度量`。
3. 当前成熟度取“所有必需能力均至少达到 1”的最高等级。平均分不能抵消关键能力缺失。
4. 没有证据时按 0 计；仅有口头描述不能作为完成证据。
5. 维度得分取该维度所含能力的平均值，保留一位小数，用于排序改进项，不单独决定等级。

## V1：可开发

- 有需求记录；
- 有任务；
- 有Git分支；
- 有基础测试；
- 可以完成本地开发。

判定要求：以上五项均至少为 1。

## V2：可稳定交付

- 有DoR和DoD；
- 有CI门禁；
- 有测试策略；
- 有数据库迁移规范；
- 有测试环境和发布验证。

判定要求：已达到 V1，且以上五项均至少为 1；CI 门禁和发布验证至少达到 2。

## V3：可生产运行

- 有灰度或功能开关；
- 有日志、指标和告警；
- 有故障恢复；
- 有安全扫描；
- 有数据质量监控。

判定要求：已达到 V2，且以上五项均至少为 1；日志/指标/告警和故障恢复至少达到 2。

## V4：可持续优化

- 有交付效能指标；
- 有AI开发质量指标；
- 有自动化治理；
- 有架构债务管理；
- 有持续复盘和流程改进。

判定要求：已达到 V3，且以上五项均至少为 2；至少一项治理能力达到 3。

## 证据示例

| 能力 | 可接受证据 |
|---|---|
| DoR / DoD | 模板、已完成 Issue/PR、门禁记录 |
| CI 与测试 | 流水线配置、最近运行结果、失败阻断记录 |
| 数据库迁移 | 迁移脚本、演练记录、对账和恢复方案 |
| 发布 | 发布单、staging 验收、发布后验证记录 |
| 可观测性 | 仪表盘、告警规则、值班或响应记录 |
| 安全 | 扫描配置、漏洞处理记录、权限审计 |
| 效能与改进 | 交付指标、复盘、改进项关闭记录 |
