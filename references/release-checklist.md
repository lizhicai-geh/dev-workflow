# 发布就绪检查

## 发布前

AI 为每项写入 `通过 / 失败 / 不适用`、证据位置和时间：

| 门禁 | 状态 | 自动化证据 |
|---|---|---|
| 必需 CI 和独立 AI 审查通过，版本及变更范围明确 | | |
| staging 自动验收与环境配置验证通过 | | |
| 数据库迁移及执行顺序已验证 | | |
| 发布策略、恢复演练、监控和告警验证通过 | | |
| 外部授权边界状态明确 | | |

按风险选择直接、滚动、蓝绿、金丝雀、功能开关或按租户/用户灰度。

## 发布后

- **技术**：成功率、延迟、错误率、资源、数据库、队列和第三方调用正常。
- **业务**：为本系统定义核心流程完成率、处理成功率、转化或对账指标。
- 由 AI 按观察窗口采集基线、阈值、异常和验证结论；超阈值时自动触发停止、回滚或向前修复策略。

## 阻断

存在未接受的 P0/P1、CI 或 staging 失败、迁移不可验证、恢复方案缺失、核心监控缺失，或所需外部授权未取得时，结论为 No-Go。生产发布若需要外部授权，授权只决定是否执行，发布、观察和验证仍由 AI 完成。
